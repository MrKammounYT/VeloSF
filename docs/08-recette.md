# Recette – un test par cas d'utilisation (CU1 à CU12)

Chaque cas a un **test automatique** de l'API (`npm test`, fichiers `server/test/cuXX-*.test.ts`) qui couvre le scénario nominal, les scénarios alternatifs et les exceptions de `02-cas-utilisation.md`, et un **scénario manuel** dans l'interface (base remise à zéro par `npm run seed`, code secret `1234`).

| CU | Test automatique | Scénario manuel (interface) | Résultat attendu |
|---|---|---|---|
| CU1 Gérer les stations | `cu01-stations.test.ts` | Responsable → Stations → « + Nouvelle station » « Route El Ain », capacité 10, clic sur la carte → Enregistrer → Modifier → Supprimer. Puis modifier « Sfax Centre » avec capacité 10. Puis supprimer « Sfax Centre ». | Station créée puis supprimée. Refus « capacité inférieure au nombre de vélos présents (17) ». Refus « la station contient 17 vélo(s) ». |
| CU2 Acheter un vélo | `cu02-achat.test.ts` | Achat de vélos → série VS-0301, CycloTun, Ville, Bleu, Gare de Sfax → Enregistrer.
